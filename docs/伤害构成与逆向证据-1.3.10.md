## 服务端结算与客户端演出的边界

当前 `net.gd`、`game.gd` 与 `main.gd` 表明真实请求结果由服务端下发；`battle_view.gd` 的深渊回放读取事件里的伤害、技能、状态和护盾。该文件同时保留旧本地演出计算分支，不能把这些旧公式当成现行深渊服务端实现。

服务端没有随客户端发布完整伤害生成代码、每一步乘区及随机数种子，因此本版提供**真实回执的伤害账本与构筑快照**。现有本地推演继续用于候选比较，预测区间不包含模型误差，不宣称逐次命中可与服务器完全一致。

精确重放已收到的伤害，与预测服务器尚未生成的伤害，是两种不同能力。本版没有为满足“全还原”而编造未下发的来源、装备贡献或服务端乘区。

## 字段核对

| 字段或来源 | 已确认的含义 | 本版处理 |
|---|---|---|
| `side=ally,dmg>0` | 己方命中事件的伤害数值 | 按角色与事件相加 |
| `reaction` / `rel` / `skill` | 事件携带的反应、遗物、技能标记，可同时存在 | 主表按反应→遗物→技能→无来源标记互斥归类；关联表允许重叠 |
| `crit` | 本次暴击标记 | 统计暴击命中数、暴击伤害，不反推暴击增伤净贡献 |
| `tick` | 周期命中标记，可能包括引导多段 | 称为周期标记，不能统一解释成燃烧等持续伤害 |
| `canal` | 明确的引导标记 | 单列引导命中，优先于一般周期类别 |
| `element` | 本次明确下发的元素 | 只使用此字段统计元素拆分 |
| `burnEl`、`burn`、`slow`、`venom`、`marks` | 命中回执携带的状态信息 | 不作为本次攻击元素或伤害来源；状态统计可以重叠 |
| `esc` / `sesc` | 护盾快照 | 不相加为伤害 |
| `relc` | 遗物计数条标记 | 不相加为伤害 |
| `castOnly` | 明确的纯施法事件 | 单列施法标记，不把命中数当施放次数 |
| `dmg<0` | 回执的治疗数值 | 单列治疗，不从输出中扣除 |
| `result.sima.dano` | 结算生命损失 | 与敌方事件伤害分开 |
| `truncated` | 服务端标注回执截断 | 事件明细按已收到部分展示；不补造缺失事件 |
| `result.danoUnidad` | 部分回执提供的单位汇总 | 审计对照；本次旧实测6场截断回执中它等于已收到事件总和，不能据此擅自补伤害 |

同一事件主来源只计一次。目标、元素和命中类型拆分分别与该来源总额守恒；技能参与量、遗物触发量和状态关联量可能交叉，不能再加到主表总额。

## 每场实际技能与历史数据

桥接0.3.6在操作发出前冻结参战英雄的账号属性、技能等级、装备状态、冷却与动态描述。只保留参战英雄，采用白名单并深复制、递归脱敏；后续换装、升级或名称变化不会改变已经归档的战斗上下文。

例如本机狂战士10级上挑实际说明为 **310%**、冷却 **6.8秒**，静态目录基础说明为130%。本版以当场实际说明显示310%；旧场次没有快照时明确显示未采集，不填入现在的310%，也不把基础130%说成当场倍率。

同ID技能也可能跨职业复用（例如弓箭手和圣骑士的`juicio`）；说明按职业及当场技能表读取。聚合多场不同构筑时保留各版本说明和场数，不用最后一场覆盖全部历史。

账号面板可能尚未包含本轮深渊遗物、祝福、敌方防御与状态修正。界面明确标为战前账号属性，不能直接乘技能倍率就宣称得到服务器最终命中。

旧摘要可以从身份匹配的本地原始归档只读重算，原始回执与旧摘要对象均不改写。没有相应归档或字段时保留缺失状态。
