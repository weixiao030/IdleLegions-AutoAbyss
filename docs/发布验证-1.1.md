# 1.1 自选职业与站位验证

日期：2026-11-09。Windows x64；前端使用现有 React / Radix Themes / Phosphor，按 design-taste-frontend 做局部改进。

## 职业来源

只读解析本机 Steam 游戏包的 Godot 4.7 PCK 目录，深渊英雄卡资源 `assets/ui/sima/tarjetas/heroe_*.png.import` 共 8 类；对 `i18n/strings.zh_CN.translation` 的 OptimizedTranslation 哈希表逐项查找，确认以下名称与游戏简体中文翻译一致。

| 内部 ID | 游戏中文名 |
| --- | --- |
| berserker | 狂战士 |
| arquera | 弓箭手 |
| healer | 治疗师 |
| asesino | 刺客 |
| paladin | 圣骑士 |
| medico | 瘟疫医生 |
| mago | 法师 |
| cruzado | 十字军 |

游戏 EXE / PCK 的 SHA-256 与修改前基线一致。发行包包含原创职业清单，不包含提取的游戏资源、游戏程序、账户数据或凭证。

## 行为与兼容性

新配置与恢复默认均为：前排狂战士、法师；后排弓箭手、圣骑士。已有合法配置保持原样。四位各选不同职业；选择已经上阵的职业会交换位置，前移与后移可以跨前后排。这里前排与后排表示从最前到最后排列时的前两位与后两位；入场仍通过游戏原接口传递完整的有序英雄 ID。

保存站位只保存阵容，不提交其他未保存的参数草稿；保存全部参数仍包含阵容。磁盘写入成功才更新内存。运行时前后端均禁止保存站位。已入场的深渊保持原队伍，下次入场使用新方案。

## 验证范围

- .NET 编译零警告、零错误；Windows 自包含 EXE 构建成功。
- 65 项后端自测通过，覆盖全部 1,680 个四职业有序组合、非法输入、旧配置保持、保存与重新加载、其他参数保留、八职业入场请求的真实 ID 与顺序，以及已有策略回归。
- 隔离集成主机调用生产 HTTP 处理器并提供嵌入的生产前端，不连接真实游戏，也不写玩家配置。浏览器 23 项检查通过：四个选择器均列出全部职业、32 种逐位选择、交换与跨排移动、独立保存与刷新恢复、保存全部参数、非法请求、保存失败重试、运行中禁用、已有深渊提示等。
- 桌面及 1024、768、390 像素宽度均未发现页面或职业选择器溢出；浅色、深色和手机下拉菜单均已查看。

本版验证了入场请求的职业映射与顺序；没有为测试而消耗玩家绳索或新增真实下潜。历史真实战斗数据见 0.4.3 报告，不作为本次自选阵容的真实战斗结果。

本地证据在 `output/formation/`。可重跑隔离主机：`dotnet run --project tools/formation-integration -- output/formation`，再使用 `browser-check.cjs` 检查该主机页面。
