# 1.3.5 本地发布验证

## 结论与范围

本文件记录2026-11-10发布前的本地验证；线上发布状态以GitHub Release为准。Windows x64自包含EXE已构建，未启动真实游戏、未消耗玩家资源。桥接仍为0.3.2，不必因本次目标设置重新安装。旧版冻结收集与选牌兜底回归保留。

## 用户报错的调查

这是用户侧反馈，不归咎于本机或对方硬件。截图包括AggregateException、空引用、Collection was modified与原生0xc0000005。普通冷快照/单线程学习下旧版没有在本机复现，因此不声称已精准还原用户机器运行条件。

隔离并发测试用同一Simulation实例同时学习战斗样本与评估候选，在保存的旧Simulation.cs复现AggregateException/NullReferenceException，堆栈位于Evaluate对enemies.Where(p => p.Dps > 0 ...)的枚举（旧代码第199行）；并发写List在枚举时可导致集合异常或空引用。该机制与截图同类，但尚不能单凭截图证明用户触发路径完全相同。

修复：Learn与Evaluate的数据准备共享modelGate；所有JsonNode读取、条件解析与模型集合枚举移到串行准备区，并行区只使用提取后的数值数组、不可变技能记录及每候选独立状态和随机数；Bridge的缓存快照给每个调用者独立树；错误日志保留完整堆栈。没有设置一个低次数上限或把用户次数偷偷改为10。原生0xc0000005无用户dump，不能保证已确认它的唯一原因。

## 实际验证

- 正式release EXE --self-test --self-test-dir运行512项全部通过，隔离目录不读写真实游戏。
- 每候选100、1000、2000、3000、5000次，各24轮×24候选，合计6,393,600次真实本地试验均通过；固定种子重复一致。
- 本机运行时识别16逻辑处理器；另用DOTNET_PROCESSOR_COUNT=48验证高核数调度配置，重复同组6,393,600次试验通过。此环境变量不是48核物理硬件测试，不冒充用户电脑实测。
- 同模型3000次学习与8路×20轮×24候选并发评估，修复前空引用、修复后通过；48处理器调度声明下同样通过。
- 正式EXE另覆盖四人八敌的1680个分散候选×2000次，以及4096个自由分配候选×3000次，均没有缩水；千万次配置可运行中取消。
- 四人四敌开启为24种一对一，关闭为256种可集火；四人两敌为6种二对二；倒地不分配、复活重新纳入。真实生产Pilot.Step通过真实文件Bridge派发四个不同目标，隔离fixture只模拟回执，不操作游戏。
- 浏览器原34项+新增26项=60项通过；自动保存/刷新、键盘、导入导出、运行锁、旧配置、新默认及1440/390浅深色均验证；无横向溢出及未处理异常。已查看新增设置截图，沿用Radix/Phosphor/青色样式，无新增依赖。
- 默认参数JSON与生产Settings序列化逐字段一致；package-lock仅本项目根版本变更，第三方依赖与HEAD完全一致。

## 默认值与兼容

默认分别锁定=true，模拟=2000，纯电清冻结模型假设=true，允许骨库伏击=true，允许精英路线=true，avoidEliteIds=[sg_alferez]（共享清单真实陪葬旗官）。普攻带电仍false，纯电清冻结仍明确为服务端未确认的本地模型假设。

旧配置缺字段按新默认；已有明确数值、false、空名单不静默覆盖。若旧用户要采用新预设，先导出备份，再导入包内默认参数。
