# 1.5.1 发布验证

日期：2026年11月12日。Windows x64；本机16个CPU逻辑线程、约47.2 GiB总内存，NVIDIA GeForce RTX 5070 Ti（约16GB显存），驱动617.42；.NET SDK 8.0.421。桥接仍为0.3.6。

## 当前行为

主导航新增独立“策略 5–7 参数”页，说明三种策略的参数作用，提供 Auto / 手动选择。旧配置默认手动；Auto 根据实际主机的逻辑线程数与总内存选择起始预算，后端加载、保存和开始时核对数值，页面显示实际采用值。Auto 不开启CUDA，保留训练设备与自动训练开关。低内存或读取失败时保守降档；分档不代表CPU测速或固定等待时间。

训练设备CPU / CUDA默认为CPU。CUDA执行网络前向、梯度归约及参数更新；MCTS、模拟、推理及留出验证继续使用CPU。ILGPU与ILGPU.Algorithms固定1.5.3，保留NCSA许可，无需CUDA Toolkit、Python或PyTorch。设备或显存失败时，从未修改的初始权重用CPU重训，独立验证未改善时保留旧模型。

策略一、三、四的冰川 / 冰4前置、七系各4张及满系后单卡收益规则已修正。策略四光系“使用此配置”默认关闭，启用及关闭不改已有单卡设置。首页“策略说明”弹窗列明七套策略的规则、优点、局限及适用情况。

监控实战时修正唯一合法操作仍完整搜索的等待：无分支直接进入独立预测与回执核验，保留暂停条件和价值学习轨迹，不伪造搜索访问数或策略标签。多候选仍执行搜索预算。另修复重复选择当前选项时，保存提示停在“待自动保存”的问题。

## 已通过的隔离验证

- Debug完整自测1036项；Release正式单文件EXE完整自测1036项，退出码0。两者均启用FROST_TEST_CUDA=1并实际执行CUDA内核，未将CPU回退计作CUDA成功。
- CUDA双头与共享主干梯度通过独立有限差分校验，最大误差约8.03e-12；重复训练数值一致。
- 人工6次下井夹具共120条，按整次下井划分训练80条、验证40条。GPU执行60批，验证损失0.19466降至0.11317后发布模型v1；可重启并用CPU加载。
- 注入显存分配失败后实际用CPU重训，显示回退原因；结果与相同种子的纯CPU训练一致。
- Auto覆盖低线程、低内存、未知内存及四档边界，保持训练开关独立，后端拒绝未知模式；唯一操作不搜索、不伪造标签且响应暂停。
- 前端39项测试通过。原搜索/CUDA/光配置浏览器33项回归通过；新增独立Auto页面25项及重复选择保存1项通过；七策略说明弹窗14项通过。
- 浏览器覆盖1440/768/390宽度、明暗模式、Auto保存与刷新、手动切换、后端归一化、CUDA独立关闭、运行锁定、光配置保留原单卡和冰锥遗物/徽章区分。

## 复现与证据

设置FROST_TEST_CUDA=1，运行正式EXE的 --self-test --self-test-dir <隔离目录>。WinExe使用Start-Process -WindowStyle Hidden -Wait并核对退出码与self-test.json。未设置显卡测试开关时，通用自测无需GPU，仍覆盖配置和失败回退。

本次证据：output/auto-page-debug-self-test/self-test.json、output/release-auto-page-self-test-v151/self-test.json及对应search-fixture/cuda-training-evidence.json；output/search-page-regression-final.json、output/auto-page-regression-final.json、output/strategy-guide-browser-result.json。隔离主机不连接真实游戏，不消耗绳索，不写玩家真实训练目录。

## 限制

CUDA功能测试使用独立人工夹具，不能当成真实爬层或搜索提速成绩。少量样本可能比CPU慢；默认使用第一张可见CUDA显卡，未提供多卡选择。Auto只提供容量上的保守起点，CPU代际、游戏负载及模拟规则仍影响实际耗时。
